## Mandatory invariants

1. Plaintext DB is never uploaded; any plaintext temp is private, short-lived and tied to exact generated artifact identity.
2. No recovery-ready state without authenticated manifest, ciphertext integrity, available key version and stated verification level.
3. Destination outcomes cannot overwrite each other; a Drive success never upgrades failed S3 primary.
4. No deletion of last verified point, in-flight object, active restore/drill reference, held item or divergent object.
5. Recovery starts no worker until database target, configuration/key, storage, recovery mode and queue quarantine checks pass.
6. Historical destructive WebsiteJobs/queue payloads never automatically replay after rollback.
7. No public/customer/operator endpoint changes platform destination secrets or offers unrestricted production restore.
8. Drive account has only the confirmed scope/folder needed; platform S3 credential cannot reach customer prefixes.

## Gate classification

**M9 closure blockers:** dedicated S3 bucket/policy verification, separate credential, encryption/authenticated manifest/readback, independent key and APP_KEY retrieval evidence, MySQL 8.4 CI/import/boot, queue replay safety proof, required CI green, staging integration validation if runtime changes, no unresolved critical/high issue.

**Owner/provider decisions:** provider versioning, Object Lock, replication, distinct account/region and cost. The residual common-provider risk remains even after bucket separation.

**Optional:** Drive implementation/OAuth activation and provider drill. **M12:** cancellation/deletion/legal holds. **M10:** full notification/alert routing; M9 defines only signals/health contract.
