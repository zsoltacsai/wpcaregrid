# M14 Preflight Capability Matrix

No capability in this table is a universal support guarantee. Detection should produce `PASS`, `WARN`, `BLOCK`, or `UNKNOWN`; unknown capability must not be presented as supported.

| Capability | Detection proposal | Supported? at planning baseline | Warning/blocker | Customer message | Operator detail / fixture |
|---|---|---|---|---|---|
| Connector pairing, version and HTTPS | authenticated handshake, server/plugin capability matrix, URL scheme | Existing protocol; current staging reports Connector 0.4.5; host-wide matrix missing | block unsupported version/HTTP in production; unknown TLS is blocked | “Connection requirements are not met” | reason code, TLS/version, no secret; old/current Connector fixtures |
| WordPress/PHP compatibility | Connector runtime versions and versioned tested product matrix | capability-specific; CI code is not proof for all customer hosts | warn outside tested range; block if operation contract unsafe; unknown restore/write compatibility fails closed | compatibility status and next step | versioned PHP/WordPress matrix fixtures; explicit multisite/custom-root flags |
| Filesystem root and permissions | Connector checks exact configured WordPress paths, root containment, read/write/rename, symlinks | path checks exist; full environment matrix pending | block unsafe restore/update/remediation; backup can separately report partial read coverage | “Some files cannot be safely changed” | path codes and permission bits, never server absolute paths; symlink/case fixtures |
| Available disk and upload limits | PHP upload/post limits, free space estimate, max archive/object, parallel slot budget | server staging capacity is monitored; site-side capacity baseline incomplete | block restore/write if reserve insufficient; warn on constrained scans | “Not enough available space for this operation” | measured bytes/threshold and probe time; full/near-full filesystem fixture |
| Database connectivity and engine | Connector DB connection, engine/charset/table prefix and version | schema and backup manifests record engine, versions, charset; supported versions undecided | block restore when schema/engine unsupported/unknown | “Database requirements need review” | engine/version/reason, no credentials; MySQL/MariaDB fixtures |
| Archive integrity and bounds | manifest hash, compressed/uncompressed bytes, entry count, path safety, compression ratio | hashes, manifest and restore plan exist; complete resource limits not yet evidenced | hard block integrity/path/resource limit violation | “Backup cannot be safely inspected” | exact coded error; traversal, duplicate, ZIP bomb, truncation fixtures |
| Scheduled execution | Connector heartbeat, queue depth, cron signal/poll freshness, unique scheduling slot | periodic polling/scheduling exists | warn stale; block queued mutating work where stale | “Site connection is not reporting” | last check and queue-age internal details; WP-Cron off/real cron fixtures |
| External network | server-side fixed provider endpoints; Connector outbound to app | no site outbound preflight matrix | warn/block per feature for TLS failure, API unavailable or policy-denied egress | provider or connection unavailable, retry guidance | hostname/category only; no URLs with secrets; timeout/DNS/TLS fixtures |
| Restore readiness | verified backup same site, active job/restore lock, safety point and rollback prerequisites | robust service checks exist; broader host support unsettled | block if any restore, backup integrity, disk, DB, version or quarantine precondition fails | “Restore is not ready on this site” | preflight reason vector; conflict, no last-good, insufficient space fixtures |
| Multisite / network scope | `is_multisite`, network/site IDs, table prefix and network administration context | `UNSUPPORTED` for initial launch (OQ-02 approved 2026-10-16); manifest boolean alone is insufficient | detect and report; block restore, destructive, filesystem-wide and network-wide operations with unproven network/subsite scope; limited diagnostics only when proven safe | “Multisite is not supported for this operation” with safe next step | synthetic network detection/block fixtures; no support claim absent future network-level fixture and recovery evidence |
| Bedrock/custom docroot | detect `wp-config.php`, Composer layout, docroot, symlink target and supported content root | `UNSUPPORTED` for initial launch (OQ-03 approved 2026-10-16); arbitrary and unresolved custom roots are not supported | detect and report; block mutation/restore if canonical root boundaries cannot be proven; never guess root or permit symlink/root escape | “This installation layout is not supported for this operation” with safe next step | supported-standard-layout fixtures plus negative Bedrock/custom-root/symlink fixtures; do not echo filesystem paths publicly |
| Restore/write authority | capability handshake plus fresh Owner/customer authorization, per-site feature flags | several server-side gates exist; full single matrix pending | fail closed if authorization or safety point unavailable | “This action is not currently available” | authorization and gate state; negative permission fixtures |
| Security scan capability | scanner availability, rules/feed freshness, per-scanner coverage | staging scan absent; vulnerability feed unset | `UNKNOWN`/warning, never zero vulnerabilities; no unsupported scanner claim | “Some checks are unavailable” | feed age/version, Scanner coverage fixture |
