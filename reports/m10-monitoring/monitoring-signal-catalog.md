Cadences below are recommended starting points, not current runtime behavior. All timestamps are UTC in storage; render in the viewer's chosen timezone. Freshness deadlines are separate from execution cadence.

## Probe-specific rules

- HTTP/TLS probe only server-validated website origins associated with a provisioned website. Reject non-HTTP(S), userinfo, non-standard ports, literal private/reserved IPs and any DNS answer resolving into private, loopback, link-local, multicast or metadata ranges. Re-resolve and validate every redirect hop; cap redirects at 5, response bytes at 64 KiB, total timeout at 8 seconds, and concurrent probes per tenant/host. Prefer no redirect following in the first release and record redirect as its own result; enable bounded same-registrable-domain redirects only after review.
- DNS rebinding defense binds the validated resolution to the connection where the HTTP client permits it; otherwise active probing must be behind a controlled egress proxy that enforces destination IP policy. Block internal network ranges at egress too.
- TLS checks must not fetch page bodies. Capture expiry, hostname match, chain verification result, and public certificate issuer metadata only.
- Never probe customer endpoints with credentials or execute WordPress jobs as a health check.
- Customer-configured expected IP/CNAME and registrar expiry are deferred until ownership proof, safe provider APIs and product semantics exist.
