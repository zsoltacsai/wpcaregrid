# Dependency and Toolchain Trust Matrix

Audit scope: root and WordPress Composer manifests/locks, npm manifest/lock/`.npmrc`, workflow toolchain, Gitleaks and Moto setup, OS/service packages. This is a provenance classification, not a vulnerability scan result.

| Input | Current evidence | Classification | Decision |
|---|---|---|---|
| Root Composer | `composer.lock` committed; 86 production + 33 dev package entries; no custom Composer repositories; CI validates and runs `composer install` and `composer audit --locked`. Lock pins versions/references, but package artifacts still come from Packagist/GitHub over TLS. Root permits only named plugins (`pestphp/pest-plugin`, `php-http/discovery`); post-autoload Laravel discovery executes. | LOCKED + external registry trust | Preserve lock installs and audits; review plugin allowlist and diffs on updates. No global `--no-scripts` recommendation because Laravel package discovery is required; make script behavior explicit. Audit both root and WordPress locks. |
| WordPress Connector test Composer | `wordpress/composer.lock` committed; 28 dev package entries; no custom repository; `allow-plugins: {"*": false}`; CI lock-installs and audits. | LOCKED + external registry trust | Keep test harness isolated. No Connector runtime install script is implied by lock. |
| npm | `package-lock.json` v3, 157 package records; 150 registry `resolved` entries, 0 non-registry resolved URLs and 0 missing integrity values for resolved packages. `.npmrc` says `ignore-scripts=true`; nine locked packages declare install scripts, which are suppressed. `npm ci`, explicit first-party `npm run build`, `npm audit --audit-level=high`. | LOCKED + external registry trust | Keep `npm ci`, lockfile and audit threshold. Do not use `npm install` in CI. Reassess lifecycle-suppression behavior if Vite/build dependencies change. Review the complete transitive lock diff for updates. |
| Composer version | `tools: composer:v2`; staging accepts any Composer 2.x. | BOUNDED_MOVING | Keep current maintained Composer 2 patch; log/record observed version and test upgrades. Exact patch pin would delay fixes and is unnecessary if lockfiles and validations remain authoritative. |
| PHP | `PHP_VERSION=8.4`, runtime asserts major/minor 8.4. | BOUNDED_MOVING | Track current maintained 8.4 patch. Record actual version in CI/deploy provenance; avoid pinning a stale security patch. |
| Node | `NODE_VERSION=22`, deploy asserts major 22. | BOUNDED_MOVING | Track maintained Node 22 patch; capture actual version for release receipt and update through reviewed PR. |
| Runner | `ubuntu-24.04`. | EXTERNAL_MAINTAINED | Keep ephemeral GitHub-hosted runner; its image/tooling moves. Do not self-host for “control”. Pin critical app dependencies independently and review runner-image notices. |
| Gitleaks | Workflow uses `8.21.2`, released 2024-10-28; downloads a tarball with curl and pipes directly to tar; release has checksum file. GitHub latest observed `8.30.1` (2026-03-21), with checksum asset. | VERSIONED BUT UNVERIFIED DOWNLOAD | Update to a reviewed supported release, verify published checksum/signature before execution, stage archive in `$RUNNER_TEMP`, inspect members, bounded extraction, no execution on mismatch/truncation. Future version updates are PR-only. |
| Moto | `pipx install 'moto[server]==5.1.*'` | BOUNDED_MOVING / UNLOCKED TRANSITIVES | Replace wildcard with reviewed exact tested version. For reliable CI, pin full server dependency closure with hashes in a requirements/constraints lock; update in PR. |
| MySQL/MariaDB services | `mysql:8.4`, `mariadb:10.11`; no `latest`. | BOUNDED_MOVING | Keep major/minor tags as deliberate patch-current policy for disposable test services, add scheduled reviewed validation/update. Digest pin only if a concrete reproducibility failure warrants it, with a fast digest update process. |
| Ubuntu apt | Installs `openssh-server` from Ubuntu 24.04 signed package repositories on ephemeral runner. | EXTERNAL_MAINTAINED | Accept maintained signed distro trust and moving security updates; avoid brittle exact apt pin. Keep installation limited to isolated test job. |
| Test DB credentials | `ci-root-password`, generated random per-run app DB password, isolated MySQL service network; no production use. | SYNTHETIC | Public synthetic constant is not a production-secret leak. Continue generate/mask derived user password and keep service inside the ephemeral job. |

No direct Git URLs, arbitrary HTTP package sources, local path workspaces, or non-registry npm tarballs were found. Composer package lock entries naturally include upstream Git source references while installs prefer distribution archives; they are not manifest-level VCS dependencies. Both Composer audits run with lockfiles; npm fails at high/critical. Audit data may lag and a clean audit is not proof of absence of vulnerabilities. Advisory exceptions must be package/advisory-specific, reachability assessed, mitigated, owned, and expire; no permanent ignore list.

No dependency-review action is currently configured. Do not add one until public-repository/account support, permissions and data behavior are verified; lock-diff review plus current audit gates are a sufficient initial M14 control. No formal SBOM is required now: preserve lockfiles, test/audit outputs and Connector source/package checksums. Revisit formal SPDX/CycloneDX if a consumer or M17 requirement emerges. No SDK or new dependency is proposed.
