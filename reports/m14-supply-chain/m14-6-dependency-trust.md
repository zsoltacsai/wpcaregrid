## Cache scope readback

The workflow has one cache consumer: `setup-node` npm package cache keyed by the committed npm lockfile; no manual `restore-keys`, cached build output, secrets, artifacts, or cross-run PR artifact deployment exists. GitHub documents that fork `pull_request` runs can read default/base branch caches, but caches written by a pull-request run are scoped to its merge ref and cannot be restored by the base branch or sibling PRs. The low-trust cache write restriction also prevents untrusted events from writing into default-branch scope. Integrity-locked `npm ci` still validates packages fetched from cache. Residual: cache contents are not signed and cache reads expose their contents, so do not cache secrets or executable build outputs. See [GitHub dependency caching security and scope](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching).
