## M147-F07 follow-up — single authoritative index publication (2026-10-19)

Review of the prior two-rename sequence established the failure case: if the raw feed rename succeeds and the active-index rename fails, the raw feed path contains the newly downloaded feed while the authoritative `.index.json` remains the prior version. Repository search found no runtime reader of the raw `feed_path`; `WordfenceFeed` reads only the index. Therefore the scanner continues to use the previous validated index, and a later successful sync can recover. The mismatch does not itself make the scanner report CLEAN, but it can mislead manual review of the cached raw file and leaves two apparent sources with different generations.

The follow-up removes the two-file publication pattern. HTTP feed bytes remain in a temporary file; the complete index is built in an isolated same-filesystem staging directory. A legacy raw cache is removed only if it is a regular non-symlink file, before the active index is replaced. An unexpected path type or failed removal aborts before publication. `AtomicIndexPublisher` then performs the sole checked same-filesystem rename to the authoritative index path. If that publication fails, the previous active index remains byte-for-byte unchanged; the raw cache may be absent, but cannot contradict it. The next valid sync can publish normally.

Regression evidence on the PR branch: active-index publication failure injected immediately before rename preserves the prior index and cleans temporary artifacts; a subsequent successful HTTP sync publishes the replacement. A directory at the legacy raw-cache path blocks publication safely. A two-process atomic-publisher stress test repeatedly reads the active JSON while two complete staged documents race to replace it; every observed file hashes to the old or one complete new document. The affected feed/posture file passed 17 tests / 858 assertions; the complete security feature suite passed 105 tests / 2,503 assertions; Pint passed.

**Disposition:** the reproduced scanner-index preservation defect is fixed on the review branch, pending exact-new-head CI and Owner review. The old raw-cache mismatch has no runtime consumer in this repository and did not cause a false CLEAN result. Remaining gaps: no command-level serialization or monotonic ordering for two concurrent downloads (last successful atomic publisher wins); no live feed provenance/licensing or production filesystem validation; no process-kill fault injection at the exact rename syscall boundary. M147-F07 remains OPEN pending those bounded criteria and the final PR review.
