## Interpretation and limits

The table below reconciles each registered route's declared middleware and transport boundary. It does not infer controller effects from HTTP methods, nor infer tenant isolation from a route parameter. `URI model refs` identifies the route-bound identifiers only; actual parent-child scope must be established in controller/service/policy tests. `Area feature suite` means the referenced suite has relevant coverage, not that every route has a positive behavior test. For each row, exact per-object positive/negative behavior remains **not exhaustively proven** unless a test is identified in the evidence notes. This is intentional: the route-role crossover matrix is not a substitute for a valid two-tenant object/action matrix with zero-side-effect assertions.

CSRF classification: browser state-changing routes use the `web` group, which includes Laravel `PreventRequestForgery`; `stripe.webhook` is the sole explicit exemption and its signature boundary is `AcceptStripeWebhook`. The `/api/v1/connector/*` routes use the API group; authenticated routes use `connector.auth`, and the initial `/pair` route uses its dedicated pairing limiter before a connector exists. Read-only routes are marked `N/A — no browser state change` for CSRF. Robots directives are not authorization controls.

Limiter values below are exact route middleware aliases/inline limits from runtime route-list output. Missing route middleware on read-only routes is not treated as a gap. Logout endpoints are the explicit unthrottled state-changing exception. Stripe retries are controlled by signature verification and webhook idempotency, not a route throttle.
