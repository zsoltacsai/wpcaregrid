# M14 Threat Model

**Scope:** WP CareGrid Laravel control plane, WordPress Connector, external providers, queues, backup/restore, Owner/Operator/customer surfaces, CI and staging deployment. Source review baseline: primary `62fc2a74f2b0720e61b73d70c449639363a0eead`.

Severity here is an initial planning rating based on impact and plausible tenant blast radius. It is not a vulnerability finding. No Critical/High exploit was confirmed in this bounded planning pass.

| ID | Threat / path | Initial severity | Current controls observed | Required M14 validation |
|---|---|---:|---|---|
| T01 | Tenant A reads or mutates tenant B via UUID/IDOR on web/API | High | customer middleware, policies, scoped nested bindings, UUID routes; authorization matrix tests | enumerate every object/action including export, restore, provider and async jobs; two-tenant negative tests |
| T02 | Owner privilege/session compromise reaches customer, credential or platform settings | High | separate `owner` guard, owner middleware/abilities, login throttle, sensitive-action limiters and audit | RBAC review, session revocation, re-auth coverage, stale-tab/double-submit tests |
| T03 | Operator permission escalation or use of Owner-only configuration | High | separate operator guard; explicit `operator.*` abilities; disabled operator check; full-admin switch default false | enumerate all permission combinations; attempt cross-console and forbidden config mutations |
| T04 | Connector bearer theft or replay permits site/job access | High | random `cgc_` bearer checked against stored credential hash; exact website UUID binding; HTTPS required by production default; endpoint throttles | token rotation/expiry/replay recovery contract, leakage paths, rate-limit and concurrency tests |
| T05 | Malicious Connector/site response floods or forges state | High | strict validation, whitelisted job types, bounded job delivery and request limits are present | adversarial payload size/depth/path/version fuzzing; partial/error state truthfulness |
| T06 | Website probe SSRF reaches loopback, RFC1918, link-local or cloud metadata via DNS/redirect | High | `PublicOrigin`, `PublicAddressLookup`, pinned request options and `SafeRedirect`; explicit tests exist | adversarial IPv4/IPv6, alternate encodings, DNS rebinding, redirect chain and resolver race tests; preserve authorized private-host policy explicitly |
| T07 | Restore/archive path traversal or symlink race writes outside WordPress root | High | Connector `PathGuard`, `FileRestorer`, symlink refusal, file-plan checks and hashes | fixture-based traversal/collision/symlink/time-of-check races; expanded-byte/member limits; rollback proof |
| T08 | Forged/replayed Stripe webhook duplicates or alters billing state | High | Stripe SDK signature verification, webhook inbox, event-ID uniqueness/idempotent processing | verify timestamp tolerance, replay boundary, key rotation, duplicate/race and failure behavior without real charge |
| T09 | Backup object or platform DB backup exfiltration via credential/scope failure | High | private disks, storage credentials separated by config namespace, object checksums, protected paths | provider IAM read/write/delete scope evidence, prefix containment, key recovery, data access/restore authorization |
| T10 | CI artifact/dependency/secret compromise contaminates release | High | CI read-only contents permission, dependency audit, full-history redacted Gitleaks, exact mandatory jobs; guarded staging deploy | action pinning/permissions, artifact provenance, branch protection, secret context minimization, rollback lineage audit |
| T11 | Staging deployment target or SSH identity confusion | High | deployment script hardcodes staging branch/URL/paths, strict verified host key in operations, lock, prebackup and rollback protection | independent script review, target allowlist, host-key rotation runbook and operator command confirmation tests |
| T12 | Queue job executes against wrong website after stale model/tenant change | High | jobs usually carry internal identifiers and re-fetch current state; services lock key transitions | inventory every job/event; prove owner/website relationship rechecked at execution and idempotency under duplicate workers |
| T13 | CSRF against authenticated Owner/Operator/customer mutation | Medium | browser routes use `web`; only Stripe webhook is excluded in `bootstrap/app.php`; `EnforcesCsrf` tests | route-wide state-changing action inventory; explicit exclusion assertions; Origin/SameSite and sensitive flow tests |
| T14 | Stored/reflected XSS through Owner content, site labels, findings or provider values | Medium | Blade escaping, content sanitizer/schema validation and CSP/security headers infrastructure | audit raw HTML/attributes/JSON script sinks, sanitizer allowlist, CSP deployment mode/reporting and adversarial strings |
| T15 | Credential leakage through logs, UI, exception payload or package artifact | High | deployment docs prohibit logging secrets; encrypted Owner Integration Credentials; secret scan in CI | inspect every credential display/exception/log; masking and rotation acceptance tests; package/backup scans |
| T16 | Rate-limit or resource exhaustion through pairing, uploads, scan ingestion, export, restore or Owner provider calls | Medium | named limiters for login, Connector, account, checkout, Owner/Operator external and actions; upload caps in backup config | compare every public/mutating route to limiter; per-token/site/tenant fairness; byte/depth/queue bounds and retry storms |
| T17 | Malicious dependency or WordPress package supply-chain change | High | lockfiles, Composer/npm audits, connector release gate and package consistency checks | provenance/signature verification, reviewed lockfile updates, pinned action versions, connector artifact reproducibility |
| T18 | Unsafe unserialization / deserialization gadget chain | High | session serialization is JSON; source search found no application `unserialize()` use in scanned paths | verify complete source/dependency surface and third-party archive/data parsers; malformed payload tests |
| T19 | Provider credential compromise enables broad object/DNS/mail/billing changes | High | encrypted Owner-managed credentials and explicit service config boundaries | least-privilege IAM, scope/rotation evidence, separate test/prod creds, emergency revoke path |
| T20 | Stale Owner/admin-access grant survives intended expiry/revoke | High | time-bounded admin access requests, revoke/expire commands, one-time handoff | verify active session behavior on revoke/expiry, connector/site races and audit completeness |
| T21 | Malware remediation or plugin deactivation damages customer site | High | remediation default off; requires recent verified full backup; reversible quarantine; explicit operator workflow | test every gate, backup freshness, one-action limits, partial rollback/restore lock; no unattended expansion |
| T22 | Recovery or privacy replay is skipped and stale personal state is exposed | High | recovery quarantine middleware, external tombstone journal and replay readiness; destructive-retention gate off | prove every mutation-capable entry point/job/scheduler obeys quarantine before pilot |
| T23 | AI provider configuration accidentally authorizes sensitive data transfer or autonomous action | High | no current AI provider integration/configuration found in app/config/routes | disabled-by-default provider registry, explicit data classification/approval, no key-derived authority, audit/egress tests |
| T24 | Backup retention policy or entitlement drift deletes required recovery points | High | restore/safety/latest verified point protections; customer retention settings currently environment-driven and no plan defaults | canonical versioned GFS model; monotonic safe overrides, active-restore/last-good blockers, dry-run and delete gate separation |

**Threat inventory:** 0 confirmed Critical findings; 0 confirmed High vulnerabilities; 21 High-priority threat scenarios and 3 Medium-rated scenarios above (threat count includes risk cases, not discovered defects). All High scenarios require test evidence before M14 closure. Existing staging scanner warning is an open M14 closure gate, not a finding-free result.
