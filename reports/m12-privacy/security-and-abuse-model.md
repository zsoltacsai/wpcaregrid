# Privacy security and abuse model

| Threat | Existing exposure / attack | Planned control | Required regression/evidence |
|---|---|---|---|
| Cross-tenant export/deletion (IDOR) | UUID routes and tenant data; exports/deletion do not exist | derive tenant from authenticated customer; relation-scoped queries, policy check on every task and download | two synthetic tenants; guessed UUID, altered relation, queued job and signed-link tests return no cross-data |
| Account takeover triggers erase | Password reset/email compromise | recent-auth step-up, independent confirmation, alert, rate limit, cooling-off only if approved; cancel on verified account recovery | simulate takeover/replay and cancellation race |
| Export package leakage | Private backup filesystem exists; export does not | private disk, envelope encryption if required by risk, random ID, short-lived authenticated one-time download, no logs/body | inspect headers/access logs, expiry, another-tenant access and storage cleanup |
| Secret leakage through inventory/export/logs | encrypted credentials and encrypted Stripe webhook payload; queue failures and free-form notes may contain context | strict field allowlists, logger redaction, no secrets export, exception normalization, scan generated artifacts | Gitleaks/secret-pattern + sentinel secret in job/webhook/error then assert absent |
| Unauthorized object deletion | customer storage adapter can delete; manual command can confirm last verified artifact | separate delete permission, preview/dual confirmation, bounded scope, last recovery and active-use locks, provider-readback | wrong prefix/bucket/tenant, in-use and last-point refusal, ambiguous timeout remains pending |
| Backup substitution/checksum spoofing | hash/manifests and provider metadata; threat model includes compromised storage credential | authenticated encryption and signed/authenticated manifest keyed separately; bind backup ID/environment/DB identity, anti-replay; independently verify | flip, replace and replay artifact/manifest; recovery blocks |
| Key loss or APP_KEY compromise | encrypted identity/webhook/integration fields; platform backup keyring; secret backups | independent escrow, tested retrieval, key IDs/rotation/decryption window, dual control, never put keys in reports; restore matching APP_KEY with DB | restore old/new key cases and audit; no key in logs/exports |
| Restore resurrects erased data or stale destructive jobs | M9 already quarantines some queue records in recovery mode; no privacy tombstone replay | off-domain deletion ledger; queue quarantine; replay and reconcile before workers/webhooks; explicitly cancel stale website jobs under audited rules | restore synthetic pre-erasure DB; verify tombstone reapplied and destructive job not run |
| Retention race with backup/restore/export | scheduled `backup:retention`; object loops may partially succeed | row locks/lease and idempotent task; common exclusion registry, generation check; no overlap with active restore or export | parallel duplicate workers, crash mid-object sequence and resume |
| Provider OAuth/token theft | no Drive integration active; S3/SMTP/Stripe credentials exist | least privilege, secret vault, short-lived tokens, CSRF/state, revocation/reconnect and audit | revoked/rotated credential tests; no provider response leaks |
| Free-form audit/security notes contain data | `security_incident_events.note`, error and result JSON | guidance/validation, redacted structured fields, retention class, role restrictions, export exclusion pending legal rule | inject emails/tokens/path secrets and verify redaction/export boundary |
| Retention misconfiguration/mass delete | customer retention is configurable; no central legal policy | versioned policy, dry-run diff, immutable approval reference, rate/batch limits, kill switch, last-good guard | policy reduction does not execute; replay idempotent; kill mid-batch |
| Hidden failed-infrastructure dependency | deletion ledger/tombstone only in restored DB could roll back | independent durable journal with tested recovery and key escrow; reconcile with current identity provider | restore stale snapshot and replay records created after snapshot |

No safe design makes backup encryption or hashing alone a privacy solution. Review IAM separation, encryption key access, signed URLs, temporary file cleanup, path traversal, webhook signature validation, CSRF and audit integrity as separate controls. Threat-model review must include storage provider versioning/delete markers and remote administrator access.
