# GO-5.3 helper upgrade

`go53-upgrade-helper.py` replaces only the installed initializer helper and its manifest. It requires the exact pinned pre-upgrade or post-upgrade hashes, package file hashes, unchanged contract and both AppArmor profile hashes, inactive G1 units, and a stable `mysql.service` MainPID. It fingerprints both instance datadirs and their logs before and after the operation. No MySQL command, service start, initialization, AppArmor reload, or datadir write is part of the transaction.

The tool takes an exclusive `flock` on the existing libexec directory for the full transaction; no lock file is created. It writes a root-owned mode-0600 journal containing the pinned OLD/NEW maps and base64 backups of the two original files, then fsyncs the journal and containing directory before replacement. Each target is replaced by a same-directory temporary file, file fsync, atomic rename, and directory fsync. On ordinary failure, it restores both old files and verifies their hashes. If the process is killed between replacements, the next invocation validates the journal and both target hashes, restores the exact OLD pair, and only then starts a fresh upgrade. Corrupt journals, unknown hashes, failed restoration, or ambiguous temporary state stop for manual investigation. A completed target pair is idempotently verified.

Run only after the package itself has been acquired and verified, and only under a separate Owner GO. This tool does not authorize restore initialization or GO-5.4.
